# 案 C（両方を保存して突き合わせる）試作の報告

この試作は使い捨てです。決めたいのは「AI が SolidCraft で自由に 3D を編集でき、間取りを直してもその編集が予測どおりに引き継がれ、広さと 2D が 3D に追従する家を、どんなデータで持つか」です。案 C では、住宅データと SolidCraft の文書の両方を正として保存し、要素 ID と文書のフィーチャー・ボディの対応表（bindings）でつなぎます。

再現するコマンドは上と同じ `cargo run -p candidate-c` です。

出力は次のとおりです。
- `steps.jsonl` は各段階の観測で、1 行に 1 件です。先頭行はもとの家（BASE）です。
- `notes.jsonl` は段階の後に測った補足です（斜めの面の重心の移動、家具の所属）。
- `revisions/*.json` は各段階の保存物そのものです。
- `display/*.mdsp` は表示データ、`plans/*.svg` は 2D の平面です。

数値は、この Mac で dev プロファイル（依存クレートは opt-level 2）を使い、1 回だけ実行して測ったものです。時間は目安として読んでください。

## 1. データの形

整理の軸は、安定した要素 ID をキーにした型付きのレコードです（`House` と `Bindings`）。

**住宅データ `House`。** 間取りの意味、広さ、2D の正です。
- `lines` は通り芯です（`x_w`, `x_v1`, `x_v2`, `x_e`, `y_s`, `y_sp`, `y_n`）。軸と位置を持ち、文書の同名パラメーターに 1 対 1 で写します。
- `walls` は `{line, from, to, thickness, rank}` です。
  - 端の処理は `rank` で決めます。格上の壁と交わる端は相手の厚みの半分だけ縮めます。格下の壁と交わる端は同じだけ伸ばします。
  - 角は留めではなく突き付けです。
- `rooms` は `{use, x:[line,line], y:[line,line]}` の長方形です。内法は各辺を覆う壁の厚みから導きます。壁で閉じない辺があれば検証で落とします。
- `openings` は `{host, kind, along, z}` です。
- `paints` は `{wall, side, color}` です。
- `stairs` は `{room, origin, width, rise, steps, tread}` です。
- `furniture` は `{room}` だけを持ちます。形は文書側にあります。

**SolidCraft の文書。** 形の正で、AI の自由な編集も入ります。
- 生成フィーチャーは、通り芯パラメーターの式で書きます。例は `v1-lower` の `solid.box {"corner":["x_v1 - 60 mm","y_s + 100 mm",0],"width":"(y_sp - 60 mm) - (y_s + 100 mm)"}` です。
- 開口は `targets` を壁 1 枚に限った切り取りの箱です。色は `appearance.assign` です。
- 文書を生成するのは最初の 1 回だけです。その後は追記、`parameters.change`、`timeline.edit`、`timeline.delete` だけで変えます。

**bindings。**
- `elements` は、要素 ID から生成フィーチャーの ID、ボディ名、依存パラメーターへの対応です。
- `ai` は、AI の編集 ID から `{features, bodies, depends_on, anchors, targets, room, engine_dependents_of}` への対応です。`engine_dependents_of` は、`timeline.dependents` が実際に返した依存先の記録です。
- `paints` は、色の ID から `{body, face_name, point}` への対応です。

**保存物。** 1 版ごとに `{"schema":1,"house","bindings","solidcraft":<Document>}` を 1 つの JSON にします。検証 1 の `03-moved.json` と同じ形です。

## 2. AI の操作の形

- **`house.*`。** `move_line`、`delete_wall`、`add_opening`、`move_opening`、`paint`、`add_stair`、`move_stair` です。住宅データの上で検証してから文書に反映するので、住宅の決まりは壊せません。
- **`cad.edit`。** `{"id","dependsOn","room"?,"commands":[SolidCraft のコマンド]}` という形です。参照の書き方は 2 通りあります。
  - パラメーターへの錨。S2 は `"x_e + 150 mm"` や `"y_n - 110 mm"`、S4 は `"st1_x + 220 mm"` と書きました。
  - 面への貼り付け。S1 と S5 は `sketch.create {"plane":{"face":[x,y,z]}}` で壁の面に貼りました。

各段階の JSON は `aiOperation` に、住宅の決まりを壊しうるかは `couldBreakHousingInvariants` に記録しました。

## 4. Q1〜Q7

**Q1 正の置き場所。** 両方に置きます。
- 住宅データは、通り芯、壁、部屋、開口、色の役割、階段、家具の所属の正です。
- 文書は、AI の編集を含めた形の正です。
- 文書の通り芯パラメーターは住宅データの写しです。書き換えてよいのは `house.*` だけです（X1.2）。

**Q2 3D の変更の表し方。** 追記したフィーチャーと、`ai` の binding の組で表します。参照の仕方は錨の式か、面への貼り付け（`exact_face`）です。色はタイムラインの外の appearance の登録と、`paints` の binding（保存した面の名前）で持ちます。

**Q3 引き継ぎの規則。**
- 「ついていく」は、パラメーターか面を参照していれば SolidCraft の再評価だけで起きます。
- 「消える」は、削除時に依存の閉包（`depends_on` と `timeline.dependents` の和）をとって起こします。
- 「残る」は、dependsOn が空の編集です。

壊れたときの検出は次のとおりです。
- 検出できたもの。評価エラー、Reselect（X2）、`failing`、効果のない切り取り（X5）、分裂、3D だけの部屋の変化（X1）。
- 黙って起きるもの。錨なしの不追従（X3、警告だけ）と、住宅データが知らない穴との重なり（X4）。

**Q4 広さと 2D。**
- 計算は住宅データの通り芯と壁の厚みから、内法の長方形として行います。
- 照合は、壁ボディを `sketch.intersect` で XY 平面に切った断面と比べます。高さはまず 2300 mm、閉じなければ 2060 mm を試し、部屋の中心から 250 mm 以内に重心があるプロファイルを対応させます。差は全段階で 0.000 m² でした。
- 弱点もあります。S2 で r6 は 2300 では閉じず、2060 で照合しました。アーチの頂部、ドアの上端、斜めの加工が重なると、閉じる高さがなくなりえます。差が 0 なのは、壁が箱だからでもあります。

**Q5 保存。**
- 1 版は 7,659〜15,492 B（圧縮なし）です。大半は文書で、住宅データは約 2.2 KB、bindings は 1.5〜2.2 KB です。
- 読み込みは全体の再評価で、56〜140 ms でした。
- 操作は 0.4〜820 ms でした。最大は S4.2 です。12 回の `timeline.dependents` と検査用の断面 4 回が効いていると推測しますが、プロファイルはとっていません。
- 表示データは 30,656〜85,992 B です。

**Q6 upstream。** 変更していません。足りない部分は外側で補いました。
- 断面の命令がないので、`sketch.intersect` で代えました。
- 消えたボディの色の登録は `appearances.faces.retain` で片付けました。
- 面へのスケッチは、`body` を渡すと `index` も必須なので、点だけで指定しました。

**Q7 AI の操作。** どれも 1 回の指示で書けます。`house.*` は住宅の決まりを壊せません。`cad.edit` は、AI が SolidCraft の座標と錨を正しく書く前提に立っています。守りは 3 段です。
- 静的な検査。dependsOn のボディとパラメーターだけを参照できます。`parameters.*` と `timeline.*` は禁止し、名前の重複も禁止します。
- 実行後の検査。評価エラーがないこと、閉じていること、切り取りや join が何かを変えたこと、部屋の断面が不変であることを確かめます。
- すべての操作に共通の audit。全ボディが要素に対応していることを確かめます。

違反すれば、住宅データ、bindings、文書をまとめて戻します。

## 5. 規則の数

引き継ぎの規則は 6 個です。
1. 移動は `parameters.change` にします。参照するものはすべてついていきます（S1.2、S2.2、S3.2、S4.3、S5.3）。
2. 式で書けない生成側の入力は `timeline.edit` で変えます（X2）。
3. 削除は依存の閉包をとり、色の登録を片付けます（S1.3、S5.4）。
4. 部屋の統合では小さい方の ID を残し、所属を付け替えます。
5. dependsOn が空の編集には触れません（椅子）。
6. 住宅側の追加はタイムラインの末尾に足します（S3.3、S4.1）。

安全の規則は 4 個です。
1. 失敗、Reselect、`failing`、対応のないボディがあれば全体を戻します。
2. `cad.edit` の静的な検査を行います。
3. `cad.edit` の実行後の検査を行います。
4. 錨のない編集に警告を出します。

色にもドアの追加にも、特別扱いは要りませんでした（S3.3）。

## 6. 壊れやすいところ

1. **住宅データは AI の形を知りません（X4）。** フィレットのように縁を参照する編集があれば Reselect で止まります。なければ黙って形が崩れます。
2. **錨なしの編集は黙って追従しません（X3）。**
3. **トポロジーが変わるパラメーター変更は、黙ってボディを分けます。** audit で拒否はできますが、検証 2 のように対応を付け直す処理は作っていません。
4. **壁の接合が、生成フィーチャーの式に焼き込まれています。** 壁の分割や交点の変化には `timeline.edit` での書き直しが要ります。これは未検証で、いちばん大きな穴です。
5. **作り直せません。** 面の名前に `F<id>` が入るためです。文書は履歴を抱えて増え続け、読み込みのたびに全体を再評価します。
6. **パラメーターが二重にあります。** 人が SolidCraft を直接触ると食い違います。読み込み時の照合は作っていません。
7. **面に貼ったスケッチの軸を取り違えやすいです。** 原点は世界原点を面に投影した点で、x 軸は −Y でした（X5）。
8. **`timeline.dependents` は名前を返します。** 名前の重複で取り違えるので、重複は拒否しました。
9. **色の登録はタイムラインの外にあります。** 削除のたびに片付けが要ります。

## 7. 自己採点（5 点満点）

- **R1 5。** 15 段階すべてが数値で一致しました。
- **R2 3。** 差 0 で、評価エラーは 0 件でした。ただし X3 と X4 という黙った道が残っています。分裂は拒否するだけです。断面の照合は、閉じる高さがある前提に立っています。
- **R3 3。** 引き継ぎの規則は 6 個です。ほかに安全の規則が 4 個要り、接合の書き直しは未実装です。
- **R4 3。** どれも 1 回の指示で書けました。ただし AI が座標と錨を正しく書く前提です。
- **R5 4。** 7.7〜15.5 KB、56〜140 ms でした（1 回だけの実測）。文書は縮みません。
- **R6 5。** upstream を変更していません。

## 8. 考えて捨てた別案

- **留めの輪郭スケッチ（検証 6）。** 頂点をすべて式にする必要があるので捨てました。箱なら移動が純粋なパラメーター変更になります。代わりに角は突き付けです。
- **斜めの加工を面に貼ったスケッチで描く。** 面の座標は絶対座標なので、壁が伸びても楔は動きません。錨の式を選びました。
- **作り直したうえで AI の編集を当て直す（案 A）。** `F<id>` が変わり、C の良さが消えます。
- **統合した部屋に新しい ID を振る。** ID の安定を優先しました。

## 9. 取り込みたい改良

案 A から取り込みます。壁を加工する AI の編集を、住宅データにも部品座標の「加工」として登録します（例：`v1-lower` に along 2500〜3400、z 0〜2250 のアーチ）。
- 住宅側の検証が AI の穴を知るので、X4 を拒否できます。
- AI は壁に沿った座標で書けるので、X5 も起きにくくなります。
- 文書には、これまでどおり錨の式で書いたフィーチャーとして入れ、追従は SolidCraft に任せます。
