# 案 B の試作報告：SolidCraft の文書だけを正にする

この試作は使い捨てです。目的は、案 B が S1〜S5 をどこまで満たし、どこで SolidCraft とぶつかるかを、実際に動かして確かめることです。

- コード: `candidate-b/src/main.rs`
- 各段階の観測: `reports/candidate-b/steps.jsonl`（25 行）
- 各段階の 2D と表示データ: `reports/candidate-b/<場面>-<段階>.svg` と `.mdsp`
- 実行ログ: `reports/candidate-b/run.log`
- 再現: workspace のルートで `F6_ROOT=. cargo run -q -p candidate-b`（約 7 秒）

## 1. データの形

正は SolidCraft の `Document` だけです。住宅の意味は、文書の中のラベルで持ちます。文書の外に対応表は持ちません。

| 置き場所 | 中身 | 例 |
|---|---|---|
| user parameters | 間取りの寸法 | `W`=12000 mm（東の外壁の芯）、`D`、`split`、`v2x`、`spineY`、階段の `st_x`・`st_y` |
| user parameters | 部屋ごとの種の点。寸法の式で書く | `rm_r2_x = (split + v2x) / 2`、`rm_r2_y = spineY / 2` |
| feature の名前 | `<elementId>/<role>`。一つの要素の feature は一緒に生き、一緒に消える | `wall.v1-lower/profile`、`door.d1/cut`、`ai.arch1/cut` |
| body の名前 | element id | `wall.v1-lower`、`stair.s1`、`furn.chair1`、`ai.shelf1` |
| appearances | SolidCraft の面の色（名前と点） | `{body: wall.v1-lower, name: F12:start, point: [3940,3000,1200]}` |
| metadata `jp.instantmadori.labels` | 部屋の用途だけ | `{rooms: {r1: {use: LDK}, …}}` |

組み立て方は次のとおりです。

- 壁は 1 枚ずつ、sketch と extrude で作ります。動く寸法は式にします。v 壁は YZ 面の sketch を `offset: "split - 60 mm"` に置きます。南北の壁は断面を描いて `distance: "W + 200 mm"` で押し出します。
- 角は突き付けです。留めとスラブは作っていません。
- 開口は、式で位置を決めた `solid.box` の cut です。`targets` には母体の壁だけを書きます。

文書から導くもの（保存しないもの）は次のとおりです。

- 部屋の輪郭と広さ
- 壁のどちらの面がどの部屋に向くか（`wallSides`）
- 家具や階段がどの部屋にあるか（`roomMembership`）
- 開口と壁の結びつき（cut の `targets`）

## 2. Q1〜Q7

**Q1 正の置き場所。** 文書だけです。保存は `doc.to_json()` の 1 本です。壁を消すと、その壁のラベルも feature と一緒に消えます。そのため、ラベルと文書がずれることは構造上起きません。

**Q2 3D の変更の表し方。** AI の変更は、`ai.<id>/<role>` という名前の feature として文書に足します。既存の形への参照は三通りです。

- 寸法の式で参照する。S1 のアーチ、S4 の段鼻、S5 の棚がこれにあたります。
- 点で指して SolidCraft の名前を保存する。S2 の chamfer と、X2 の丸窓の `references` がこれにあたります。
- 絶対座標で書く。S5 の椅子がこれにあたります。

**Q3 引き継ぎの規則。** ほとんどは SolidCraft の参照の意味で決まります。

- 式で書いた変更はついていきます。
- 名前で参照した変更は、名前のついた形についていきます。
- 母体が消えた変更は一緒に消えます。
- 絶対座標の変更は残ります。

サービスの規則は 3 つと、止める条件が 1 つです（§5）。Reselect は評価のエラーとして必ず出ます。黙って起きる壊れ方は 2 つ残りました（X1 と X5）。

**Q4 広さと 2D。** 3D とラベルだけから出します。

1. scratch のセッションで `wall.*` の body をすべて `sketch.project {body}` で z=0 に投影します。
2. 種の点の下の profile を `solid.extrude {profiles: [{point}], exact_regions: true, distance: 1}` で選ばせ、体積を測って面積にします。
3. 輪郭の多角形は、投影した線分の配置から自前で作ります。
4. 二つの種が同じ領域に入ったら、合わさった部屋とします。

照合の結果は次のとおりです。

- 全段階で、SolidCraft の面積、自前の多角形の面積、寸法から計算した内法の面積が一致しました。
- z=2300 の断面による照合は、S2 以外で偏差 0 でした。
- S2 では、斜めの加工で north に隙間ができ、r6 の断面の領域が閉じず、照合できませんでした。

投影を選んだのは、ドア、窓、アーチ、斜めの加工のどれも、上から見た平面形を欠かないからです。

**Q6 upstream。** 変更していません。消えた body に残った色の項目だけは、`doc_mut().appearances.faces.retain(..)` で消しています。

**Q7 AI の操作。** AI に見せるのは SolidCraft のコマンドの batch です。サービスはこれをチェックポイントで包んで原子的に実行し、その後に §5 の規則を当てます。どの変更も 1 回の batch で表せました。

住宅の決まりは事前には守れず、評価の後に検査するだけです。

- 見つけられたもの
  - Reselect（X2c）
  - 種の点が壁の中に入ったこと（X3）
  - ラベルのない部屋（X3）
  - 部屋の合流（S1.3、X4）
- 見つけられなかったもの
  - 絶対座標の置き去り（X1）
  - 壁の端が宙に浮くこと（X4）
  - 色の広がり（X5）

AI は parameter の名前、式の構文、座標の向きを知る必要があります。たとえば XZ の sketch では y が −Z を向きます。

## 4. 自己採点

- **R1: 4。** 16 段階すべて pass です。満点にしないのは、pass が「AI が式か名前で書いた」ことに依存するからです（X1）。
- **R2: 3。** 広さは 3D と偏差 0 でした。ただし、黙って起きる壊れ方が 2 つあり、断面の照合が使えない場面があり、接合の健全さは検査できません。
- **R3: 3。** 規則は 3 つと止める条件 1 つです。ただし、ついていくか残るかは、変更の書き方で決まります。
- **R4: 2。** 1 回の batch で表せますが、AI が知るべき SolidCraft の約束が多く、決まりは事後の検査でしか守れません。
- **R5: 4。** 26〜60 KB、55〜171 ms です。
- **R6: 5。** upstream は変更していません。

## 5. 引き継ぎの規則（サービスの規則 3 ＋ 止める条件 1）

SolidCraft の参照の意味としてそのまま効くもの（数えない）は次のとおりです。

- E1 式はついていく。
- E2 点で指した面や稜線は名前についていく。消えるか合わさると Reselect になる。
- E3 色は名前の stem、次に保存した点で探す。点は更新されない。

サービスの規則は次のとおりです。

1. **C1** `unknown body` で失敗した feature を消す。消えるものがなくなるまで繰り返す。
2. **C2** 同じ element id の feature をまとめて消す。`timeline.delete` は sketch を残すため。
3. **C3** 消えた body に残った色を消す。
4. **G1** Reselect などのほかの失敗は消さず、変更を止めて報告する。

部屋の導出の規則も 4 つあります。

- 合流したら若い id を残す。
- 種が壁の幅の領域に入ったらエラー。
- 種のない部屋の大きさの領域はエラー。
- 壁は `wall.` で始まる body とする。

## 6. 壊れたこと、やりにくかったこと

1. `sketch.inspect` の profile は、一本の線を複数回使うループでも、各線を一度しか挙げません。最初の版は r1 を 1.416 m²（spine の平面形）と誤りました。面積は SolidCraft に点で選ばせて測り、輪郭は線分の配置から作りました。
2. 断面の高さを一つに決められません。ドアは 2050、アーチは 2250、S2 の斜めは東端で 1800 まで下がります。
3. Reselect が起きます（X2c）。自動で選び直す仕組みはありません。最初の C1 は失敗をすべて消していたので、この失敗を黙って消していました。
4. 面一の合流で色が広がります（X5）。
5. 色の保存した点は古くなります。S3.3 では、点が新しいドアの穴の中に入りました。名前で解決できたので正しく出ましたが、名前が切れたときの代わりの点は、もう面の上にありません。
6. 面の名前は役割になりません。v1-lower の r1 側は `F12:start`、r2 側は `F12:top` でした。向きと部屋は毎回幾何から導きました。
7. AI が知るべきことが多くあります。
   - XZ の sketch では y が −Z を向く。
   - 面に貼る sketch は `body` と `index` も要る。
   - 稜線は数値の点で指す。
   - 動く壁に付ける物は、その壁の parameter の名前で式を書く。
8. 壁の接合を表せません（X4）。

## 7. 考えて捨てた案

- **ラベルを文書の外に置く。** 二つ目の正になります。
- **部屋を壁の面のラベルで持つ。** 一つの面が 3 部屋に面することがあり、分割や合流のたびに付け直しが要ります。
- **断面で部屋を出す。** 自由な加工と両立しません。照合用に残しました。
- **全部の壁を一つの thin extrude にする。** 壁ごとの id と面ごとの色を失います。
- **AI の変更を、面に貼った sketch に統一する。** 局所座標を知る手段が要り、面が割れると Reselect になります。
- **失敗した feature を無条件に消す後始末。** X2c で、無関係な変更を黙って消すことが分かりました。

## 8. 取り入れたい改良

A から、部品の座標系で加工を書くことを取り入れたいです。

- 各壁が、自分の parameter で動く構築平面（例: `wall.v1-lower/frame`）を文書の中に持ちます。
- AI の壁付けの加工は、必ずその平面の上で局所座標で書きます。
- これで AI は parameter の名前も式も知らずに済み、X1 は構造上起きなくなります。

C から取り入れるなら、壁の接合と部屋の境界を小さな住宅データとして持つことです。X4 と事前の検査を補えます。ただし、それは二つ目の正を持つことになり、B の利点を手放します。
