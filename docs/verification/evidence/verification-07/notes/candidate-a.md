## 結論

- S3.4 では、色を塗った面を本当に四つに分けました。色は四つの面すべてに残りました。
- 負の対照 N1〜N8 では、壊す操作を 8 つ試しました。8 つとも検出または拒否できました。

## データの形

住宅データは、安定した要素 ID をキーにした型付きのレコードを `BTreeMap` に入れて持ちます。`BTreeMap` の順序が、作り直すときの決まった順序にもなります。

| レコード | 中身 | 備考 |
|---|---|---|
| `nodes` | `id → [x, y]` | 壁の端点。T 接合の点も節点として持つ |
| `walls` | `id → {a, b, t}` | 節点 2 つと厚さ。向きは a→b。L 側と R 側は向きに対して決まる |
| `rooms` | `id → {use, boundary: [(wall, ±1)]}` | 反時計回りの境界の列。+1 は壁を a→b に歩く（部屋は L 側）。輪郭は境界の壁の内側の面の線を順に交わらせて導く |
| `openings` | `id → {wall, kind, offset, width, sill, head}` | `offset` は壁の始点からの距離 |
| `paints` | `"wall/side" → {wall, side, color}` | 壁と側（L/R）で 1 つ |
| `stairs` | `id → {origin, dir, width, rise, run, steps}` | 1 本の直階段が 1 つの立体 |
| `modifiers` | `id → {host, operation, sketch, face?}` | AI の 3D の加工。下で説明する |
| `objects` | `id → {anchor, commands}` | 家具と造作。下で説明する |

**加工（modifier）。** host は二種類です。

- 壁に付ける場合は `{kind:"wall", wall, ref:"start"|"end"}` を持ちます。座標系の原点は基準の端の中心線上、z=0 です。u は壁に沿って内側へ、z は上へ向きます。
- 階段に付ける場合は `{kind:"stairTreads", stair}` を持ち、段板ごとに座標系を作ります。原点は段鼻の左端です。

`sketch` は SolidCraft のスケッチ描画の命令の列です（`sketch.line`、`sketch.arc.three_point` など）。座標は host の座標系の (u, z) で書きます。作り直すときは、SolidCraft の `sketch.create {plane:{origin, x_dir, y_dir}}` で host の座標系にスケッチを置くので、テンプレートの座標を書き換えません。押し出しの深さ、向き、`operation`、`targets:[host]` は作り直す側が決めます。壁の加工は既定で貫通します。`face:{side, depth}` を指定すると、その面から決まった深さだけ削ります。

**物体（object）。** `commands` は、物体自身の座標系で書いた SolidCraft の命令の列です。立体とスケッチの名前は `<物体 ID>.` で始めます。作り直すときは、家を作る前の空の世界で原点に組み立て、`solid.move` で回転と平行移動をして置きます。anchor は二種類です。

- 部屋に付ける場合は `{room, at, rotation}` を持ちます。位置は世界座標です。`room` は導出した値で、改訂ごとに計算し直します。
- 壁に付ける場合は `{wall, side, offset, elevation}` を持ちます。物体の +x を壁に沿わせ、+y を部屋の側へ向けます。

保存するのは住宅データの JSON だけです（1,818〜4,322 B）。SolidCraft の文書（39〜85 KB）は保存しません。

## 作り直しの手順

改訂ごとに、新しい `Session` を一から作ります（`param_check = Strict`）。順序は次のとおりで、毎回同じです。

1. 物体（原点で組み立ててから移動）
2. 床板
3. 壁（輪郭を XY のスケッチにして押し出す。輪郭は接合の規則で決まる。T 接合は相手の面で止め、2 本の角は留め継ぎにする）
4. 開口（壁の座標系に長方形を描き、貫通して切る）
5. 壁の加工
6. 階段と、その段板ごとの加工
7. 色（壁と側ごとに、開口と加工を避けた点で `appearance.assign` をし直す）

改訂は「写し、検査、採用」の順に進めます。操作を写しに当て、住宅の決まりを CAD より前に検査し、作り直し、3D を検査します。どこかで失敗すれば、前の住宅データをそのまま残します。

## Q1〜Q7 への答え

**Q1 正の置き場所。** 住宅データだけです。SolidCraft の文書は毎回作る派生物です。D の検査で、同じ住宅データから作った文書の JSON と表示データがバイト単位で一致しました。だから文書を保存する理由がありません。

**Q2 3D の変更の表し方。** host に付けた加工は、host の座標系で書いたスケッチ描画の命令と、`cut` か `join` で持ちます。独立した物体は、自分の座標系で書いた命令の列と anchor で持ちます。色は壁と側の組で持ちます。どれも面の名前や番号を持たないので、作り直しても Reselect は原理的に起きません。

**Q3 引き継ぎの規則。** 規則は 8 つです（下の「引き継ぎの規則」）。壊れたときに黙って消えないよう、次の検出を入れました。負の対照 N1〜N8 で、どれも働くことを確かめました。

- 加工や開口が host を変えなかったら、失われた変更として扱う（押し出しの返り値の `changed_bodies` で判定。N2）。
- どの要素にも対応しない立体を検出する（N3）。
- 色は、側の平面の面がすべて塗られ、ほかの面が塗られていないことを確かめる。
- 住宅データの広さと 3D の断面を照合する（N1）。
- 住宅の決まりの違反は、CAD を呼ぶ前に検出する（N4〜N8）。

**Q4 広さと 2D。** 住宅データから計算します。部屋の境界の壁ごとに、部屋側の面の線を求め、隣り合う線の交点を輪郭にします。3D との照合は二通り行いました。

- 断面。scratch の Session で z=2350 に XY のスケッチを作り、すべての壁の立体を `sketch.intersect` で写し、`sketch.inspect` で領域の面積を読みました。部屋の重心に一番近い領域を選び、面積で選り好みはしません。閉じた部屋では、すべての段階でずれが 0 mm² でした（浮動小数点の誤差 4e-9 mm² を除く）。
- 壁の面。部屋の輪郭の各辺について、境界の壁の立体に、同じ平面で部屋を向いた面があるかを `model.faces` で確かめました。すべての段階のすべての辺で、ずれは 0.0 mm でした。

S2 の後の r6 は、斜めの加工が壁の上部を取り除くので、z=2350 の断面では閉じませんでした。z=1770 より下ではドア（上端 2050）が部屋をつなぐため、閉じる高さは一つもありません。r6 は壁の面の照合だけで確かめました。

**Q5 保存。** 保存するのは住宅データの JSON で、1,818〜4,322 B でした。作り直しは 58〜368 ms でした。これは 1 回だけ測った値です。candidate-a は dev プロファイル、依存は opt-level 2 で、Apple Silicon の macOS 上で測りました。ベンチマークとしての精度はありません。一番重いのは段鼻を付けた階段（S4.2 と S4.3）で、351 ms と 368 ms でした。段板 12 枚ごとにスケッチと join を作るので、命令が 89 から 137 に増えます。

**Q6 upstream。** SolidCraft は変更していません。使った機能は次のとおりです。

- 任意の平面へのスケッチ（`{origin, x_dir, y_dir}`）
- 3 点の円弧
- 対称な押し出しと片側の押し出し
- 回転つきの `solid.move`
- 点で指定する `appearance.assign`

**Q7 AI の操作。** 操作は 9 種類あり、どの段階も 1 回の呼び出しで表せました。

## R1〜R6 の自己採点（5 点満点）

- **R1 場面の正しさは 5 点。** framing の 15 段階すべてで、期待する結果を解析値と一致する数値で確かめました。framing の S3.3 では面が分かれないので、S3.4 で面を本当に分けて確かめました。
- **R2 追従と健全さは 4 点。** 断面で照合できた部屋は、ずれがすべて 0 mm² でした。壁の面との照合も、すべての辺で 0.0 mm でした。評価の失敗、宙に浮いた色、黙って消える変更はありませんでした。それでも 1 点引きます。理由は二つです。S2 の後の r6 は断面で照合できませんでした。床の輪郭を変える join は、広さが追従せず、検出して拒否するだけです（N1）。
- **R3 規則の少なさは 4 点。** 8 つの規則で全場面を説明できます。そのうち 3D の変更の引き継ぎは 6 つで、残りの 2 つは間取りの変更の規則です。特別扱いは 2 つあります。壁を消したときに壁に付いた物体を部屋に付け替えることと、部屋を統合したときに新しい ID を作ることです。
- **R4 AI の操作の形は 4 点。** どの段階も 1 回の呼び出しで表せます。部屋の境界、壁の接合、階段の配置を AI は壊せません。それでも 1 点引きます。理由は三つです。AI は壁の向きと基準の端を知る必要があります。テンプレートで表せるのは、スケッチの押し出しによる切り取りと付け足しだけです。既存の辺や面を点で選ぶ操作（アーチの縁の丸め、`solid.shell` など）はまだ入れていません。
- **R5 保存と作り直しは 4 点。** 保存は 2〜4 KB です。作り直しは 58〜368 ms でした。段板ごとの加工が命令の数を増やし、作り直しが約 4.5 倍になりました（78 ms から 351 ms）。
- **R6 upstream は 5 点。** SolidCraft は変更していません。

## 引き継ぎの規則（8 つ）

1. 開口と加工は host の座標系（基準の端からの距離、高さ、側）で持つ。host が動いても伸びても、その端についていく。
2. host を消すと、その開口、加工、色を一緒に消す。消したものは操作の結果に一覧で返す。
3. 色は壁と側の組で持ち、作り直すたびに、開口と加工を避けた点に塗り直す。分かれた面は、名前の語幹ですべて塗られる。
4. 壁に付けた物体は、壁の基準点、側、高さについていく。
5. 壁に付けた物体の壁を消すと、その時点の世界座標のまま、部屋に付けた物体へ付け替える（特別扱い）。
6. 部屋に付けた物体は、世界座標の位置を保つ。所属する部屋は、改訂ごとに計算し直す。
7. 壁を消すと、両側の二つの部屋の境界の列をつなぎ、新しい ID の部屋にする。用途は広いほうの部屋から取る（特別扱い）。
8. 壁を動かすと、その壁の上にある節点も一緒に動く。T 接合でつながった壁は伸び縮みする。

## 壊れたこと、やりにくかったこと

- **framing の S3.3 では面が分かれない。** 床から立ち上がるドアは、B-rep の面に切り欠きを作るだけで、面は 1 つのままでした（`F11:side:l3` が 1 つ）。面が本当に分かれたときの色を確かめるため、S3.4 を加えました。案 A では色を毎回塗り直すので、分かれたかどうかは結果に影響しません。
- **床の輪郭を変える自由な加工に、広さが追従しない。** N1 の膨らみは、断面との照合で検出できました。しかし住宅データの広さは変わりません。案 A では、こうした加工を拒否するか、住宅の操作（壁の厚さや位置）として表し直す必要があります。
- **断面での照合が届かない場合がある。** 壁の上部を削る加工があると、どの高さでも閉じない部屋が出ます（S2 の r6）。壁の面との照合で補いましたが、面積そのものの照合ではありません。
- **基準の端の選び方。** 加工は `ref` で始点か終点を選びます。開口は常に始点からです（不揃い）。AI が逆の端を選ぶと、加工は決まった規則どおりに動きますが、意図とは違う位置に行きます。たとえば S2 で `ref:"start"` を選ぶと、東の外壁を動かしたとき、斜めの加工は東の端から 600 mm 離れます（推測。実行はしていない）。
- **段板ごとの加工の費用。** 12 枚の段板それぞれにスケッチと join を作るので、命令が 48 増え、作り直しが約 4.5 倍になりました。
- **既存の形を参照する加工は未対応。** 丸め、面取り、`solid.shell` は辺や面を世界座標の点で選びます。host の座標系の点を世界座標へ変換すれば作れるはずですが、試していません（推測）。
- **接合の規則は最小限。** T 接合と 2 本の角だけです。3 本以上が 1 点に集まる接合（貫く壁がない場合）は拒否します。斜めの壁は試していません。

## 検討して捨てた案

- **任意の SolidCraft の命令を世界座標に書き換える。** どの引数が座標かは命令ごとに違うので、書き換えの表がすぐに大きくなります。代わりに、SolidCraft の平面つきスケッチで座標系ごと置き、テンプレートには手を入れません。
- **開口を `solid.box` で切る（shape69 と同じ方法）。** 加工と同じく、壁の座標系のスケッチで切る方法にそろえました。斜めの壁でも同じ経路で動くはずです（推測。斜めの壁は試していない）。
- **壁の中心線の平面グラフから、部屋を面として探す。** plan.md §3.1 の「向きつきの境界の列」をそのまま持つほうが、統合が列の連結だけで済み、部屋の ID も明示できます。
- **部屋を統合したとき、広いほうの ID を残す。** S5.4 の期待（所属する部屋だけが変わる）に合わず、AI にも変化が見えにくいので、新しい ID にしました。
- **改訂をまたいで Session を持ち続ける。** 検証 6 の結論どおり使いません。D の検査で、作り直しが決まった結果になることを確かめました。
- **物体を家から離れた場所で組み立てる。** 座標の書き換えが要るので捨てました。代わりに、家より前の空の世界で組み立てます。

## 他の案から取り込みたい改善

案 B の「広さを 3D の断面から取る」を、一部だけ取り込みます。部屋の境界の壁に join の加工が付いているときだけ、scratch の Session で、cut を除いた壁と join だけを作り直し、床の近くの高さで断面を取ります。cut を除けばドアや斜めの加工で部屋が開かないので、どの部屋も閉じた領域として面積を出せるはずです（推測。実装はしていない）。こうすると、N1 のような膨らみで広さが 3D に追従し、framing の「広さは 3D に従う」を、拒否ではなく追従で満たせます。住宅データの輪郭は、部屋の ID と境界の意味を持つ骨組みとして残します。
