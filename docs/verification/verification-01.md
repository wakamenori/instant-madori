# 検証1：住宅情報とSolidCraftの連動

実施日：2026-11-08。対象は住宅情報とSolidCraftの連動。入力条件と期待値は実行前に定めた。本文は実施時点の記録であり、現在の仕様と実装順は[実装計画](../plan.md)を参照する。

片付け（2026-11-08）：試作コードと `target/` の生成物は削除済み。この文書と[記録フォルダ](evidence/verification-01/)の証拠は残している。以下は実施時の記録であり、記載のコマンドは現在のリポジトリではそのまま実行できない。

**結果：この二部屋の例では、住宅情報・2D・3D・面積の連動、壁と家具の色・家具形状の維持、保存・再読込後の再編集、失敗した操作から直前の案を守ることを確認できた。** 既存のSolidCraftのクレートは変更していない。

## 目的と方式

部屋の寸法から壁・開口を変更しながら、SolidCraftで付けた色や家具の形を維持できるかを確かめる。住宅情報とSolidCraftの編集可能な設計データを一緒に保存し、開き直して変更を続けられるかも確認する。

検証アプリは `apps/madori-verify` に追加した。既存のSolidCraftのクレートは変更していない。住宅情報の共有壁位置を、SolidCraftのユーザーパラメータ `split` に渡す。壁・開口はその式を参照する。家具は別のSolidCraftのフィーチャーとして作り、住宅の更新時に作り直さない。

この検証用の住宅情報は共有壁の位置だけを変更できる。一般的な住宅スキーマ、任意の接合・配置、部屋の追加・削除への対応は含まない。家具は右の部屋に収まったままの条件とし、移動・干渉解消の自動処理は試さない。

## 実行前に決めた条件

単位は長さがmm、面積がm²、体積がmm³。面積は壁の内側で囲まれた矩形とし、出入口の敷居部分は含めない。これは検証用の定義であり、法定床面積の定義ではない。

| 対象 | 条件 |
| --- | --- |
| 室内全体 | X=0〜8000、Y=0〜5000 |
| 外壁 | 厚さ200、高さ2400 |
| 共有壁 | X位置は中心で指定。厚さ120、高さ2400、Y=0〜5000 |
| 二部屋の出入口 | 共有壁をY=1800〜2700、Z=0〜2050で切り欠く |
| 北側の窓 | 幅1200、高さ1100、下端Z=900。中心Xは共有壁中心Xの半分。移動ルールはこの例で明示的に設定 |
| 家具 | テーブル。X=5800、Y=900、天板下端Z=700、厚さ60、奥行800、当初幅1400。脚4本は80×80×700 |
| 家具の変更 | 幅1800へ変更。天板の手前中央に幅200、奥行180、深さ60の切り欠きを追加 |
| 壁の色 | ボディ全体をRGB(205,163,83)、左側の面をRGB(54,111,168)に指定 |
| 数値の許容差 | 座標0.01 mm、CAD由来の面積0.0001 m²、住宅情報の面積0.00000001 m²、体積は対象に応じ5〜50 mm³ |

| 状態 | 共有壁中心X | 左部屋 | 右部屋 | 窓中心X | 家具全体の体積 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 初期 | 4000 | 19.70 | 19.70 | 2000 | 85,120,000 |
| 色・家具変更後 | 4000 | 19.70 | 19.70 | 2000 | 102,160,000 |
| 壁の移動後 | 4500 | 22.20 | 17.20 | 2250 | 102,160,000 |
| 保存・再読込後 | 4500 | 22.20 | 17.20 | 2250 | 102,160,000 |
| 再読込後の再編集 | 4250 | 20.95 | 18.45 | 2125 | 102,160,000 |

共有壁の体積は出入口を差し引いて1,218,600,000、北側壁の体積は窓を差し引いて3,768,000,000とする。期待値は上表の寸法から手計算した固定値を検証コードに渡す。

## 確認方法

住宅情報から計算した面積と、SolidCraftの実際のB-repの壁境界から計算した面積をそれぞれ期待値と比較する。形状の寸法・体積・穴の有無はB-repの境界、質量特性、点の内外判定で確認し、メッシュからの推定値は使わない。

面の色は保存された色指定の存在だけでなく、再評価後に解決された面の位置と法線を調べる。家具の切り欠きは体積と内外判定の両方で確認する。表示用の間取り図では部屋を住宅情報から、家具を実際のCADメッシュの上面投影から描く。

変更は住宅情報とSolidCraftセッションの複製に行い、検証を通過したときだけ採用する。不正な共有壁位置と、正常な壁移動の後に不正なCAD操作を続けた場合を試し、失敗前後で保存対象全体が等しいことを確認する。

## 実施時の手順（試作コードは片付け済み）

リポジトリのルートで以下を実行した。

```sh
cargo run --locked --profile ci -p madori-verify -j 4 -- target/madori-verify
cargo run --locked --profile ci -p madori-verify -j 4 -- --resume target/madori-verify/03-moved.json
```

一つ目のコマンドは、成功時に `target/madori-verify/report.json` に検査結果と処理時間、各状態のJSONに住宅情報・対応表・SolidCraftの編集可能な設計データを保存する。同じフォルダに各状態の間取り図（SVG）と3D画像（PNG）を生成する。二つ目は別プロセスを起動し、保存データの読込と再編集を検査する。出力フォルダはGitの管理対象外であり、今回の主要な証拠は[記録フォルダ](evidence/verification-01/)にも残した。

間取り図の確認用PNGは、生成されたSVGから次のコマンドで作った。この変換だけはmacOSのフォントとImageMagickを使う。検証アプリ自体には不要。

```sh
magick -font /System/Library/Fonts/Supplemental/Arial.ttf -background white target/madori-verify/03-moved-plan.svg target/madori-verify/03-moved-plan.png
```

### 途中で直した点

検証アプリでSolidCraftの評価結果を読む箇所と、面の法線を読むためのトレイトの参照を修正した。既存クレートの修正は不要だった。

失敗テストの最初の入力には負の長さを使ったが、SolidCraftはそれを受け入れた。[箱の生成処理](../../third_party/solidcraft/crates/kernel/src/build.rs)は二つの角の最小・最大値から箱を作るため、負方向に延びる箱として成立する。検証側の前提が誤っていたため、明確なエラーになる未定義の寸法式に変更した。住宅として受け入れる寸法や関係の検査は、SolidCraftの入力検査とは別に必要である。
