# 指示の状態を見て、止める・答える・再開する・取り消す

案件画面（`/projects/<案件の ID>`）の見出しの下、案の行の下に状態の欄がある。状態の欄は、AI が指示を実行中か、順番を待っているか、質問して回答を待っているか、回答をもとに作業しているか、待機中の指示を保留しているかを一行で示し（`role="status"`）、その下に補足と、その時に押せるボタンを出す。実行中は `止める`、保留中は `再開する` と `取り消す`、質問待ちは質問の本文と選択肢のボタンと回答欄が出る。押した結果は欄の下に一行で出て、状態が先へ進むと消える。表示はすべて `GET /api/patterns/<id>/state` から決まるので、開き直しても同じ状態とボタンが出る（押した結果の一行だけは出ない）。最後の指示を止めた・完了できなかった・上限に達したときは、待機中の指示が無くても `最後の指示は…` の行が残る。

## Sub-features

- `status-running`：実行中は `指示を実行しています…` と `止める`。待機中の指示があれば `待機中の指示がN件あります。止めると、待機中の指示は保留になります。` が続く。
- `status-stop`：`止める` を押すと、押している間は `止めています…` になる。待機中の指示があれば `指示を止めたため、待機中の指示（N件）を保留しています。` と `再開する`・`取り消す`、無ければ `最後の指示は止めました。途中の変更は採用していません。` になり、どちらも下に `指示を止めました。` が出る。止める前に完了していたら `止める前に指示が完了し、案N「名前」を確定していました。` が出て、新しい案に描き替わる。
- `status-asking`：AI が質問すると `AIが質問しています。選択肢を選ぶか、回答を書いて送ってください。`、質問の本文、選択肢のボタン（`role=group[name="選択肢"]`）、回答欄（`role=textbox[name="回答"]` と `回答を送る`）が出る。待機中の指示があれば、保留の補足と `再開する`・`取り消す` も出る。指示欄の下には、指示を送ると何が起きるかの一行が出る。
- `status-answer`：選択肢を押すか回答を書いて送ると、会話の質問の直下に `回答` の行が出て、状態の欄が `AIが回答をもとに作業しています…` になる。画面は回答の仕事が終わるまで読み直しを続ける。待機中の指示があれば、終わった後に `回答をもとに案N「名前」を確定しました。待機中の指示（N件）を保留しています。` と `再開する`・`取り消す` が出る。回答の仕事の説明は回答の直下、保留中の指示より上に並ぶ。
- `status-resume`：`再開する` を押すと、保留中の指示が受付順に動き、`待機中の指示（N件）を再開しました。` が出る。
- `status-cancel`：`取り消す` を押すと、待機中の指示がすべて取り消されて保留が解け、`待機中の指示（N件）を取り消しました。` が出る。取り消した指示の行には何も付かない。
- `status-failed`：指示が失敗して待機中の指示があると、`指示を完了できなかったため、待機中の指示（N件）を保留しています。` が出る。案は最後に確定したもののまま。
- `status-limited`：上限到達の表示は [AI費用の上限](./cost-limit.md) の手順で確かめる。保留中は `上限に達して指示を終了したため、待機中の指示（N件）を保留しています。`、待機中の指示が無ければ `最後の指示は上限に達したため終了しました。途中の変更は採用していません。` になる。
- `status-reopen`：どの状態でも、開き直すと同じ行とボタンが出る。読み直しが止まる状態（保留、質問待ち、何も動いていない）では、`/state` の読み出しの回数が 5 秒おいても増えない。

## How to get to it (user POV)

- 案件画面を開く（[案件画面で案を見る](./project-view.md)）。指示は指示欄から送る（[案件画面で指示を送り、会話を読む](./project-chat.md)）。
- ボタンは状態の欄にある。`止める`、`再開する`、`取り消す`、選択肢のボタン、`回答を送る`。結果を確かめられなかった操作には `もう一度送る` が出る。
- 台本の AI は、指示の一行目が `台本:question` なら最初の往復で `和室は必要ですか？`（選択肢 `必要`・`不要`）と質問し、`台本:` に続く名前を知らなければ失敗する（例 `台本:fail`）。

## Driving it with T3 preview

Preconditions:

- Container が必要。[SKILL.md の「起動」](../SKILL.md#起動)の手順で `MADORI_DEV_JOB_TEST_HOLD=first_answer:30` を付けて起動する。仕事は台本の AI の最初の応答の後に 30 秒待つので、その間に後ろの指示を並べ、止められる。
- 状態確認が通っている。
- `$EVIDENCE/status/` がある。`. "$EVIDENCE/dev.env"` で `API` を読み込み、`D="$EVIDENCE/status"` を設定している。
- 状態の欄を読む式を控えている。`({ status: [...document.querySelectorAll('[role="status"],[role="alert"]')].map((e) => e.textContent), log: [...document.querySelectorAll('.conversation-log > li')].map((li) => li.innerText.replace(/\n+/g, ' | ')) })`

- **案件を作って開く。** `preview_open` に `target: { kind: "environment-port", port: <WEB_PORT> }`、`open: false`、`reuseExistingTab: false` を渡し、返った `tabId` を以後のすべての呼び出しに渡す。`preview_act` の `click` で `locator: 'role=button[name="新しい案件を作る"]'` を押し、`preview_wait_for` で `text: "まだ案がありません。"` と `urlIncludes: "/projects/"` を待つ。`preview_evaluate` の `location.pathname` から ID を取り、`PID=<ID>` と `PAT=$(curl -sS "$API/projects/$PID/patterns" | jq -r '.patterns[0].id')` を設定する。
- **質問させ、後ろに一つ並べる。** `preview_act` の `type` で `locator: 'role=textbox[name="指示"]'` に `台本:question` を入れて `role=button[name="送信"]` を押す。続けて `小さな平屋を作ってください。` を入れて `送信` を押す。`preview_wait_for` で `text: "待機中の指示が1件あります。"` を待つ。状態の欄に `指示を実行しています…` と `止める` が出る。撮って `$D/running.png` に写す。
- **質問を見る。** `preview_wait_for` で `text: "AIが質問しています。"` を `timeoutMs: 60000` で待つ。式の `status` が `["AIが質問しています。選択肢を選ぶか、回答を書いて送ってください。"]` で、欄に `待機中の指示（1件）は保留しています。…`、`和室は必要ですか？`、`必要`・`不要` のボタン、回答欄、`再開する`・`取り消す` が出る。`log` は `指示 | 台本:question`、`AIの質問 | 和室は必要ですか？ | 必要 | 不要`、`指示 保留中 | 小さな平屋を作ってください。` の順。指示欄の下に `指示を送ると、保留中の指示の後ろに加わります。` が出る。撮って `$D/asking.png` に写す。
- **選択肢で答える。** `preview_act` の `click` で `locator: 'role=group[name="選択肢"] >> role=button[name="必要"]'` を押す。`preview_wait_for` で `text: "AIが回答をもとに作業しています…"` を待つ。欄に `待機中の指示（1件）は、回答の処理が終わるまで保留しています。` と `止める` が出て、会話の質問の直下に `回答 実行中 | 必要` が、その下に `指示 保留中` が並ぶ。撮って `$D/answering.png` に写す。
- **回答の後に残る保留を見る。** 何も押さずに、`preview_wait_for` で `text: "回答をもとに案1「台本の案」を確定しました。"` を `timeoutMs: 60000` で待つ。欄は `回答をもとに案1「台本の案」を確定しました。待機中の指示（1件）を保留しています。` と `再開する`・`取り消す`。会話は `回答 | 必要` の直下に `AI` の説明と `案1「台本の案」` が並び、`指示 保留中` はその下。撮って `$D/held-after-answer.png` に写す。`preview_evaluate` で `performance.getEntriesByType('resource').filter((e) => e.name.includes('/state')).length` を 5 秒おいて二度読み、同じ値になる。
- **開き直す。** `preview_navigate` で同じタブを `target: { kind: "environment-port", port: <WEB_PORT>, path: "/projects/<PID>" }` に開き、`preview_wait_for` で `text: "回答をもとに案1「台本の案」を確定しました。待機中の指示（1件）を保留しています。"` を待つ。式の `log` が開き直す前と同じ順。
- **再開し、実行中に二つ並べる。** `再開する` を押し、`preview_wait_for` で `text: "指示を実行しています…"` を待つ。指示欄から `窓を大きくしてください。` と `ドアを広げてください。` を続けて送り、`preview_wait_for` で `text: "待機中の指示が2件あります。"` を待つ。
- **止める。** `止める` を押し、`preview_wait_for` で `text: "指示を止めたため、待機中の指示（2件）を保留しています。"` を待つ。式の `status` が `["指示を止めたため、待機中の指示（2件）を保留しています。","指示を止めました。"]` で、`log` の最後の二件が `指示 保留中`。撮って `$D/stopped.png` に写す。
- **止めた後の保留を再開する。** `再開する` を押し、`preview_wait_for` で `text: "待機中の指示が1件あります。"` を待つ。`窓を大きくしてください。` の行が `実行中`、`ドアを広げてください。` の行が `待機中（1番目）` になり、欄の下に `待機中の指示（2件）を再開しました。` が出る。撮って `$D/resumed.png` に写す。
- **もう一度止めてから取り消す。** `止める` を押し、`preview_wait_for` で `text: "指示を止めたため、待機中の指示（1件）を保留しています。"` を待ち、撮って `$D/stopped-again.png` に写す。`取り消す` を押し、`preview_wait_for` で `text: "待機中の指示（1件）を取り消しました。"` を待つ。式の `status` が `["最後の指示は止めました。途中の変更は採用していません。","待機中の指示（1件）を取り消しました。"]` で、ボタンは出ず、会話の指示の行には何も付かない。撮って `$D/cancelled.png` に写す。`curl -sS "$API/patterns/$PAT/state" | jq -c '{running: .runningJob, queued: .queuedJobs, hold: .queueHold, last: .lastFinishedJob.state}'` が `{"running":null,"queued":[],"hold":null,"last":"cancelled"}`。`/state` の読み出しの回数は 5 秒おいても増えない。
- **失敗で保留にする。** 指示欄から `居間を明るくしてください。`、`台本:fail`、`玄関を広くしてください。` を続けて送る。`preview_wait_for` で `text: "指示を完了できなかったため、待機中の指示（1件）を保留しています。"` を `timeoutMs: 60000` で待つ。案の行は一件目が確定した案（`確定済みの案2「台本の案」を表示しています。`）のまま。撮って `$D/failed.png` に写す。`取り消す` を押して、待機中の指示を残さない。

## Gotchas

- 30 秒の待ちの間に後ろの指示を送れないと、前の指示が先に終わって保留にならない。`送信` は続けて押す。
- 押した結果の一行（`指示を止めました。` など）は、次に仕事が始まるか終わると消える。再開の結果は、次の指示がすぐ動き出しても、動き出した後の最初の読み直しまでは残る。
- 回答の仕事が動いている間は、`再開する` と `取り消す` を出さない。回答を送っている間と、受け付けた回答がまだ state に出ていない間も、どちらも押せない。
- 待機中の指示が無い質問には、`再開する` と `取り消す` を出さない。指示欄から指示を送ると質問は閉じ、AI はその指示を回答として読む。
- 取り消した指示と、待機中に止めた指示の行には、`未実行` などの印がまだ付かない（会話の行は仕事の状態を持たない）。
- curl で操作した結果は、読み直しが止まっている画面には出ない。開き直してから確かめる。
- 片付けの前に、保留と待機中の指示を残さない。実行中の指示が残ったまま止めると、後の指示が動かなくなる（[SKILL.md の「片付け」](../SKILL.md#片付け)）。
