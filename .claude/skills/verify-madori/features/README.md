# instant-madori の検証マップ

利用者から見える機能ごとに、確かめ方をまとめた一覧。アプリを動かす前にこの索引を読み、当てはまる機能のファイルを手順として使う。準備、起動、状態確認、片付けは [../SKILL.md](../SKILL.md) にある。

## 前提

- SKILL.md の手順で、自分の worktree から `pnpm dev` を起動している。
- 状態確認で、`/api/health` と `/api/me` が期待どおりに応答している。
- 各機能の前提に Container の要否を示す。必要な機能では、起動の二つ目の確認で `200 application/vnd.madori.display; version=1` が出ることを確かめる。不要な機能だけを確かめるときは `MADORI_DEV_CONTAINERS=0` で起動する。
- 既定の利用者は `dev@example.com` で、subject は `local:dev@example.com`。

## 操作の決まり

- 画面は T3 のプレビューで操作する。要素は ARIA の役割と名前で指し、座標やタブ順に頼らない。
- Bash の呼び出しごとに、初めに `. "$EVIDENCE/dev.env"` を実行して、SKILL.md の起動の確認が書いたこの回のポートを読む。`WEB_PORT` は画面、`WORKER_PORT` は Worker のポート、`API` は画面のプロキシの API、`O` は自分の画面の Origin の見出しになる。
- API は `$API` へ送る。認証の拒否を確かめるときと定期実行を動かすときだけ、Worker のポート（`http://127.0.0.1:$WORKER_PORT`）へ直接送る。
- GET 以外の要求には `-H "$O"` を付ける。`J='content-type: application/json'` を先に設定しておく。
- コマンドは書いてあるとおりに使う。名前やフラグを変えない。
- 書き込みを伴う手順では、毎回新しい `requestId` を使う。再送を確かめる手順だけ、同じ値を使い回す。

## 証拠と未確認の報告

- 証拠のファイルは `$EVIDENCE/<機能>/` に置き、手順の名前をファイル名に入れる。
- 画面の証拠は、操作の前後のスクリーンショットと、そのときの `[role="status"]` と `[role="alert"]` の中身。
- API の証拠は、状態コードと応答本文。書き込みには、別の読み出しの結果も添える。
- 前提が欠けて通れなかった手順は、試したコマンドと欠けていた前提を報告する。別の入口で確かめたものを、その入口で確かめたと書かない。

## 機能ファイルの形

各ファイルは、H1 の題と、利用者から見える振る舞いを書いた一段落で始める。続けて、次の四つの H2 をこの順に置く。

1. `Sub-features`：短い ID と、一行の説明。
2. `How to get to it (user POV)`：利用者の入口をすべて。
3. `Driving it with <harness>`：`Preconditions:` から始め、操作ごとにコマンドと見える結果を組にする。
4. `Gotchas`：確認を無駄にしたり、結果を無効にしたりする落とし穴。

実装の詳細は書かない。利用者の経路、安定した手がかり、必要な状態、コマンド、見える証拠だけを書く。

## 機能

- [案件画面で案を見る](./project-view.md)（Container 必要）：URL で案件を開く、案の描画、実行中・待機中・保留の表示と読み直し、確定済みと編集中の表示、再読込と起動し直した後の再開、戻る・進む、間取り図と 3D の切り替え、間取り図の表示・拡大・移動・部屋と壁の選択と寸法、次の案での描き替え、3D の回転・拡大・縮小・視点の移動・視点を戻す、平面図のある階の一覧と平面図を持たない案、見つからない案件とページ。
- [案件画面で指示を送り、会話を読む](./project-chat.md)（Container 必要）：指示欄からの送信、実行中の追加の指示と待機中の表示、順の完了、会話の種類ごとの表示、未送信と同じ request ID での再送、応答だけが失われた送信の再送、狭い画面の並び。
- [指示の状態と操作](./status.md)（Container 必要）：実行中・質問待ち・回答の作業中・保留・失敗の表示、`止める`・選択肢と回答欄・`再開する`・`取り消す`、回答の後に残る保留、止める・再開・もう一度止めて取り消す、開き直したときの復元。
- [本人確認](./sign-in.md)（Container 不要）：ローカルの Access、認証の拒否、未知の経路、別の利用者。
- [案件](./projects.md)（Container 不要）：画面の一覧と作成と続きの読み込み、作成、再送、一覧、名前の変更、版の競合。
- [パターン](./patterns.md)（Container 不要）：一覧、作成、名前の変更、状態の読み出し。
- [案件名とパターン名を変える](./names.md)（Container 不要）：案件画面での案件名とパターン名の変更、再読込の後も残ること、ほかで変わった後の読み直しと知らせ、送れない名前、やめる。
- [指示を送る](./instructions.md)（Container 必要）：受付、再送、仕事の実行と案の確定、案の表示データ、案の一覧、画像の添付と、他人の資産・存在しない資産・枚数超過の拒否。
- [選んだ候補を確かめる](./pick.md)（Container 必要）：住宅データの無い案、無い案、Origin、知らない欄と長さ0の法線。住宅データを持つ案の壁は試験だけが確かめる。
- [会話を読み直す](./conversation.md)（Container 必要）：指示と案の対応、表示順、存在しないパターンと不正なカーソル。
- [指示を止める](./stop.md)（Container 必要）：待機中と実行中の停止、確定の後の停止、再送、存在しない仕事。
- [待機列の保留](./queue-hold.md)（Container 必要）：停止と失敗の後の保留、再開、取り消し、再送、古い保留への操作、保留にならない場合。
- [質問に答える](./questions.md)（Container 必要）：質問で終わった指示と保留、会話の質問と選択肢、回答が待機中の指示より先に動くこと、回答の後に残る保留と再開、答え済みと質問でないものへの回答、再送、質問待ちの停止、待機中の指示が無いときの質問。
- [画像を登録する](./assets.md)（Container 不要）：PNG と JPEG の登録、保存された行とオブジェクト、再送、形式・大きさ・幅と高さ・Origin による拒否、所有者だけの読み出しと書き換えたオブジェクトの拒否、staging での登録と読み出し。
- [AI費用の上限](./cost-limit.md)（Container 不要）：今月の上限に達したときの上限到達、会話と画面のお知らせ、上限到達での保留と再開、上限到達の指示の停止。一指示の上限は試験だけが確かめる。
- [止まった指示の復帰](./recovery.md)（案の無いパターンなら Container 不要）：実行中の指示の確かめの繰り返し、定期実行、ローカルで再読込したときの制約と止め方。
